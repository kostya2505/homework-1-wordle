# Проект 1. «5 букв»

Консольная игра в духе Wordle. Программа загадывает слово из 5 русских букв,
у игрока 6 попыток. После каждой попытки — подсказка по буквам:

```text
Загадано: озеро
Ввод:     арбуз
Результат: ❌🟡❌❌🟡

✅ буква на месте   🟡 есть, но не там   ❌ буквы нет
```

Задание разбито на три merge request'а. Делай их по очереди.

## MR1 — что уже сделано

### Структура кода

```
src/main/java/academy/fiveletters/
├── Main.java                          — точка входа, ввод-вывод
└── game/
    ├── Dictionary.java                — неизменяемый словарь + валидация
    ├── DictionaryLoader.java          — загрузка словаря из classpath
    ├── Game.java                      — фабрика игровой сессии
    ├── GameSession.java               — модель одной партии
    └── GameStatus.java                — IN_PROGRESS | WIN | LOSE
```

```
src/main/resources/
└── dictionary.txt                     — 644 слова, формат: одно слово в строке,
                                         # и пустые строки игнорируются
```

### Модель

`GameSession` хранит:

| Поле | Тип | Смысл |
|---|---|---|
| `answer` | `String` | загаданное слово (ровно 5 букв) |
| `maxAttempts` | `int` | лимит попыток (> 0) |
| `attemptsUsed` | `int` | сколько попыток уже сделано |
| `attemptsHistory` | `List<String>` | что вводил игрок |
| `status` | `GameStatus` | `IN_PROGRESS` / `WIN` / `LOSE` |

Инварианты защищены на уровне модели, а не UI:

- слово из 5 букв — проверяется в конструкторе `GameSession` и `Dictionary`;
- `maxAttempts > 0` — проверяется в конструкторе и в `Game.startGame`;
- завершённая игра не принимает новые попытки — `addAttempt` бросает
  `IllegalStateException`, если `status != IN_PROGRESS`.

### Детерминированный выбор слова

```java
GameSession session = Game.startGame(dictionary, maxAttempts, seed);
```

Одинаковый `seed` → одинаковое слово, всегда. Это возможно, потому что
`java.util.Random` даёт специфицированную последовательность чисел от seed
на любой JVM. Именно поэтому выбран `Random`, а не `SecureRandom` или
`ThreadLocalRandom`.

Проверяется тестами `SeedTest.sameSeedProducesSameAnswer` и
`SeedTest.differentSeedsProduceDifferentAnswers`.

### Словарь

Словарь содержится в текстовом файле:

```
src/main/resources/dictionary.txt
```

Формат:

```
# комментарий
автор
адрес
азарт
...
```

При сборке файл загружается через
`DictionaryLoader.load()` (не принимает аргументов — берёт `/dictionary.txt`).

Правило: `DictionaryLoader` парсит (не учитывает `#` и пустые строки),
`Dictionary` валидирует (непустой, все слова ровно 5 букв). Валидация — в
одном месте.

## Принятые решения

### Словарь отдельно от кода

`dictionary.txt` — единый источник правды для программы, тестов и
будущего smoke-теста. `DictionaryLoader` читает файл, `Dictionary` валидирует.

### Immutability по умолчанию

- `Dictionary.words()` → `List.copyOf`, наружу `unmodifiableList`;
- `GameSession.attemptsHistory()` → `unmodifiableList`;
- `Dictionary` и `Game` — `final class` с приватным конструктором.

Мутабельность осталась только там, где она неизбежна: история попыток и статус
партии. Это делает `Dictionary` потокобезопасным и позволяет спокойно
делиться им между играми.

### Fail-fast

Инварианты проверяются в конструкторе, а не в каждом месте использования.
Объект либо валиден, либо его нет. Это касается как аргументов
(`Objects.requireNonNull`, `if (words.isEmpty())`), так и состояния
(`if (status != IN_PROGRESS)`).

### Package-private «шов» для MR2

`GameSession.addAttempt` и `GameSession.updateStatus` — package-private.
MR2 (`Game.applyGuess`) сможет менять сессию, а внешний код — нет. Публичный
API сессии (то, что видят UI и тесты) при этом не расширяется раньше времени.

### Никаких интерфейсов там, где нечего абстрагировать

`GameSession` — конкретный `final class`, а не `interface` + `Impl`. Один
продукт, одна реализация. Интерфейс появится, когда появится
вторая реализация (например, replay-сессия).
