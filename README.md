# Проект 1. «5 букв»

Консольная игра в духе Wordle. Программа загадывает слово из 5 русских букв,
у игрока 6 попыток. После каждой попытки — подсказка по буквам:

```text
Загадано: озеро
Ввод:     арбуз
Результат: ❌🟡❌❌🟡

✅ буква на месте   🟡 есть, но не там   ❌ буквы нет
```

Задание разбито на три merge request'а. Делай их по очереди.

## MR1 — Данные и сессия

### Модель

`GameSession` хранит:

| Поле | Тип | Смысл |
|---|---|---|
| `dictionary` | `Dictionary` | словарь, в котором валидируются попытки |
| `answer` | `String` | загаданное слово (ровно 5 букв) |
| `maxAttempts` | `int` | лимит попыток (> 0) |
| `attemptsUsed` | `int` | сколько попыток уже сделано |
| `attemptsHistory` | `List<String>` | что вводил игрок |
| `status` | `GameStatus` | `IN_PROGRESS` / `WIN` / `LOSE` |

Инварианты защищены на уровне модели, а не UI:

- слово из 5 букв — проверяется в конструкторе `GameSession` и `Dictionary`;
- `maxAttempts > 0` — проверяется в конструкторе и в `Game.startGame`;
- завершённая игра не принимает новые попытки — `addAttempt` бросает
  `IllegalStateException`, если `status != IN_PROGRESS`.

### Детерминированный выбор слова

```java
GameSession session = Game.startGame(dictionary, maxAttempts, seed);
```

Одинаковый `seed` → одинаковое слово, всегда. Это возможно, потому что
`java.util.Random` даёт специфицированную последовательность чисел от seed
на любой JVM. Именно поэтому выбран `Random`, а не `SecureRandom` или
`ThreadLocalRandom`.

Проверяется тестами `SeedTest.sameSeedProducesSameAnswer` и
`SeedTest.differentSeedsProduceDifferentAnswers`.

### Словарь

Словарь содержится в текстовом файле:

```
src/main/resources/dictionary.txt
```

Формат:

```
# комментарий
автор
адрес
азарт
...
```

При сборке файл загружается через `DictionaryLoader.load()`
(не принимает аргументов — берёт `/dictionary.txt`).

Правило: `DictionaryLoader` парсит (не учитывает `#` и пустые строки),
`Dictionary` валидирует (непустой, все слова ровно 5 букв). Валидация —
в одном месте.

## MR2 — Правила игры

### API

```java
GuessResult result = Game.applyGuess(session, guess);
```

`applyGuess` — единственная точка входа игровой логики. Она:

1. проверяет, что партия ещё идёт (`IN_PROGRESS`), иначе `IllegalStateException`;
2. валидирует ввод (см. ниже);
3. размечает буквы по правилам Wordle;
4. фиксирует попытку в истории;
5. обновляет статус партии (`WIN` / `LOSE` / оставляет `IN_PROGRESS`);
6. возвращает `GuessResult` — нормализованный ввод, статусы букв, статус партии.

### Валидация

Ввод отклоняется, если:

- длина не равна 5;
- содержит не-буквы (цифры, знаки, пробелы);
- слова нет в словаре.

Во всех трёх случаях бросается `InvalidGuessException` — подкласс
`IllegalArgumentException`. Некорректный ввод не тратит попытку: `applyGuess`
падает раньше, чем вызывает `session.addAttempt(...)`. Опечатка — не ход.

Ввод без учёта регистра: `"ОЗЕРО"` и `"озеро"` обрабатываются одинаково.
Нормализация через `toLowerCase(Locale.ROOT)`, чтобы не зависеть от локали
машины.

### Разметка букв

Статусы (`LetterStatus`):

| Символ | Константа | Смысл |
|---|---|---|
| ✅ | `CORRECT` | буква на своём месте |
| 🟡 | `PRESENT` | буква есть в слове, но не на своём месте |
| ❌ | `ABSENT` | буквы нет среди не помеченных в ответе |

Алгоритм — два прохода:

1. Первый проход: все позиции, где `guess[i] == answer[i]`, получают `CORRECT`.
   Соответствующие буквы ответа помечаются использованными.
2. Второй проход: для оставшихся позиций ищем букву `guess[i]` только среди
   ещё не помеченных букв ответа. Нашли → `PRESENT` (и помечаем
   использованной). Не нашли → `ABSENT`.

Каждая буква ответа расходуется один раз. Это важно при повторах:

```text
Загадано: сорок
Ввод:     оооом
Верно:    ❌✅❌✅❌
```

Обе «о» в ответе уже израсходованы точными совпадениями на позициях 2 и 4.
Поэтому «о» на позициях 1 и 3 получают `❌`, а не `🟡`.

Наивная проверка «есть ли буква в слове» (`answer.indexOf(guess.charAt(i)) >= 0`)
даёт здесь `🟡✅🟡✅❌`, что неправильно. Тест
`LettersTest.repeatedLettersAreNotDoubleCounted` ловит эту ошибку.

### Финалы

- **WIN** — `guess.equals(answer)` → статус `WIN` сразу, независимо от
  оставшихся попыток.
- **LOSE** — `attemptsUsed() == maxAttempts` и не угадано → статус `LOSE`.
- После `WIN` или `LOSE` `applyGuess` бросает `IllegalStateException`:
  завершённая партия терминальна.

`session.answer()` возвращает загаданное слово в любом статусе — UI решает,
когда его показать (при `LOSE` — обязательно, при `WIN` — по желанию).

## MR3 — Интерфейс

### Меню

`ConsoleApp` — цикл «меню → игра → меню». Пункты:

```
1 - новая игра
0 - выход
```

- любой ввод, кроме `1` и `0`, печатает `Введите 1 или 0.` и возвращает меню;
- `0` завершает программу строкой `До свидания!`;
- несколько игр подряд без перезапуска — цикл `while (true)` не выходит после
  завершения партии, а снова показывает меню.

Фабрика сессии (`Supplier<GameSession>`) передаётся в конструктор — так
тесты могут создать партию с заранее известным ответом, не трогая seed.

### Игровой цикл

`GameRunner` ведёт одну партию:

- печатает `> ` и читает строку из `BufferedReader`;
- вызывает `Game.applyGuess`;
- печатает разметку, а затем одну из строк:
    - `Осталось попыток: N` — если партия ещё идёт;
    - `Победа! Слово угадано за N <форма>` — если угадано;
    - `Неудача. Загаданное слово: <answer>` — если попытки кончились;
- при `InvalidGuessException` печатает сообщение и продолжает цикл —
  некорректный ввод не тратит попытку.

Склонение слова «попытка»:

| N | Форма |
|---|---|
| 1, 21, 31, … | `попытку` |
| 2–4, 22–24, … | `попытки` |
| 0, 5–20, 11–14, … | `попыток` |

### Формат вывода

Фиксированный:

```text
❌🟡❌❌🟡 арбуз
Осталось попыток: 5
Победа! Слово угадано за 4 попытки
Неудача. Загаданное слово: озеро
```

Правила:

- разметка — пять символов без пробелов, затем один пробел, затем слово;
- на терминальной попытке `Осталось попыток` не печатается;
- `Победа!` и `Неудача.` — взаимоисключающие, печатается одна из них.

Форматирование `GuessResult` → строка живёт в `ResultFormatter`, а не в
`GameRunner`. Если формат поменяется — правится один класс.

### Детерминированный режим

```bash
./gradlew run --args="check --answer озеро --guess арбуз --guess книга"
```

Вывод:

```text
❌🟡❌❌🟡 арбуз
❌❌❌❌❌ книга
```

Код возврата: `0` — все попытки обработаны, `1` — ошибка аргументов или
отклонённая попытка.

`CheckCommand` не читает stdin и не зависит от seed: ответ и попытки задаются
явно. Это позволяет автопроверке сравнивать вывод **точно**, а не через
`contains`.

Разбор аргументов — `while` с явным индексом:

```java
while (i < args.length) {
    switch (args[i]) {
        case "--answer" -> { answer = requireValue(args, ++i, "--answer"); i++; }
        case "--guess"  -> { guesses.add(requireValue(args, ++i, "--guess")); i++; }
        default         -> { ... }
    }
}
```

`--guess` может повторяться — каждая попытка размечается в свою строку.

## Принятые решения

### Словарь отдельно от кода

`dictionary.txt` — единый источник правды для программы, тестов и
будущего smoke-теста. `DictionaryLoader` читает файл, `Dictionary` валидирует.

### Immutability по умолчанию

- `Dictionary.words()` → `List.copyOf`, наружу `unmodifiableList`;
- `GameSession.attemptsHistory()` → `unmodifiableList`;
- `GuessResult.statuses()` → `List.copyOf`;
- `Dictionary`, `Game`, `GuessResult`, `ResultFormatter` —
  `final class` с приватным конструктором.

Мутабельность осталась только там, где она неизбежна: история попыток и
статус партии. Это делает `Dictionary` потокобезопасным и позволяет
спокойно делиться им между играми.

### Fail-fast

Инварианты проверяются в конструкторе, а не в каждом месте использования.
Объект либо валиден, либо его нет.

### Разные исключения для разных ошибок

- `IllegalArgumentException` / `NullPointerException` — **ошибка программиста**:
  невалидный аргумент, `null` там, где нельзя.
- `InvalidGuessException` — **ошибка игрока**: неверный ввод. UI должен
  предложить повторить, а не падать.
- `IllegalStateException` — **ошибка порядка вызовов**: попытка хода в
  завершённой партии. UI не должен допускать такой ситуации, но модель её
  отвергает.

`GameRunner` ловит только `InvalidGuessException` — то есть ошибки игрока.

### Package-private «шов» для правил

`GameSession.addAttempt` и `updateStatus` — package-private. Менять сессию
может только `Game` в том же пакете, а внешний код — нет. Публичный API
сессии (`answer()`, `status()`, `attemptsUsed()`, …) при этом не расширяется.

### Никаких интерфейсов там, где нечего абстрагировать

`GameSession` — конкретный `final class`, а не `interface` + `Impl`.
`applyGuess` — статический метод `Game`, а не метод интерфейса `GameRules`.
Интерфейсы появятся, когда появится вторая реализация (например,
replay-сессия).

### Разделение `game/` и `cli/`

`game/` не знает про `System.out`, `BufferedReader`, `PrintStream` — только
чистая логика и данные. `cli/` знает про `game/`, но `game/` про `cli/` — нет.
Проверяется тем, что все тесты MR1/MR2 работают без консоли вообще.

Это позволяет поменять UI (на GUI, на REST, на что угодно) без единой
правки в `game/`.
